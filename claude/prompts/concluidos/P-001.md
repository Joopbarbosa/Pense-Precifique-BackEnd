# P-001 — Scaffold do projeto Spring Boot (Maven) + CLAUDE.md inicial

**Épico:** Épico 0 — Setup do Schema
**Camada:** banco/back (infraestrutura do projeto)
**Depende de:** nenhum (primeira tarefa do projeto)

---

## Contexto para o Claude Code

A pasta `pense-precifique-backend/` está vazia, exceto pelos arquivos de documentação
(`application.yml`, `backend-CLAUDE.md`, `DEPLOY.md`, `ESTRUTURA.md` e `claude/` com PRD,
Business Rules e Scenarios v6). É preciso criar o projeto Spring Boot (Maven) do zero,
seguindo exatamente a stack e a estrutura de pacotes já definidas em `ESTRUTURA.md` e
`backend-CLAUDE.md`.

**Stack (de backend-CLAUDE.md):**
- Java 21
- Spring Boot 3
- PostgreSQL 16 (Docker)
- Autenticação JWT stateless
- Migrations: Flyway (`V1__`, `V2__`... em `resources/db/migration/`)
- Documentação: Springdoc OpenAPI (Swagger) — apenas em `dev`
- Build: Maven

**Convenções obrigatórias do projeto (válidas para todo o desenvolvimento futuro):**
- Chaves primárias: UUID (`uuid_generate_v4()`)
- Soft delete: coluna `deleted_at` em todas as entidades — nunca `repository.delete()`
- Tabelas/colunas: `snake_case`
- DTOs: separados em `request/` e `response/` — nunca expor entidade diretamente
- Service: sempre interface + impl (`XxxService` + `XxxServiceImpl`)
- Regras de negócio: implementadas no `Service`, nunca no `Controller`
- Mapper: MapStruct — nunca converter manualmente dentro do Controller

**Cenário de aceite:** não há cenário BDD específico (tarefa de infraestrutura). O
critério de sucesso é: o projeto Maven compila (`./mvnw clean compile`), o `application.yml`
fornecido já existente é aproveitado/movido para o lugar correto, e o `docker-compose up`
consegue buildar a imagem do backend (mesmo que ainda sem nenhuma entidade/endpoint).

## Prompt

Cole este prompt no Claude Code:

---

Você está iniciando o projeto `pense-precifique-backend` do zero. A pasta atual contém
apenas arquivos de documentação (`application.yml`, `backend-CLAUDE.md`, `DEPLOY.md`,
`ESTRUTURA.md`, e a subpasta `claude/` com PRD, Business Rules e Scenarios). Crie a
estrutura completa do projeto Maven/Spring Boot 3 com Java 21, **sem ainda implementar
nenhuma entidade, repository, service ou controller** — apenas o scaffold.

### 1. Crie o `pom.xml` na raiz com as dependências:
- `spring-boot-starter-web`
- `spring-boot-starter-data-jpa`
- `spring-boot-starter-validation`
- `spring-boot-starter-security`
- `org.postgresql:postgresql` (runtime)
- `org.flywaydb:flyway-core` + `flyway-database-postgresql`
- `io.jsonwebtoken:jjwt-api`, `jjwt-impl`, `jjwt-jackson` (para JWT)
- `org.mapstruct:mapstruct` + `mapstruct-processor` (annotation processor)
- `org.springdoc:springdoc-openapi-starter-webmvc-ui`
- `org.projectlombok:lombok` (opcional, mas recomendado para reduzir boilerplate)
- `spring-boot-starter-test` + `spring-security-test` (scope test)
- Plugin `spring-boot-maven-plugin`
- Java release: 21

### 2. Crie a estrutura de pacotes vazia (apenas pastas, sem classes ainda) em
`src/main/java/com/penseprecifique/api/`, conforme `ESTRUTURA.md`:
```
com/penseprecifique/api/
├── PensePrecifiqueApplication.java   ← única classe a criar agora (classe principal @SpringBootApplication)
├── config/
├── controller/
├── service/
│   └── impl/
├── repository/
├── domain/
│   ├── entity/
│   └── enums/
├── dto/
│   ├── request/
│   └── response/
├── mapper/
├── security/
└── exception/
```

### 3. Mova o `application.yml` existente (já fornecido na raiz da pasta atual) para
`src/main/resources/application.yml`. Ele já contém os três profiles (base, dev, prod)
separados por `---`. Não altere seu conteúdo.

### 4. Crie a pasta `src/main/resources/db/migration/` (vazia por enquanto — a migration
V1 será criada na próxima tarefa).

### 5. Crie o `Dockerfile` na raiz, exatamente como descrito em `ESTRUTURA.md`:
```dockerfile
FROM eclipse-temurin:21-jdk AS build
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN ./mvnw clean package -DskipTests

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 6. Adicione o Maven Wrapper (`./mvnw`, `./mvnw.cmd`, pasta `.mvn/`) para que o Dockerfile
funcione sem depender de Maven instalado globalmente.

### 7. Crie um `CLAUDE.md` na **raiz** de `pense-precifique-backend/` (mesmo nível do
`pom.xml`), pois é esse o arquivo que o Claude Code lê automaticamente ao abrir o projeto.
O conteúdo deve ser uma cópia do `backend-CLAUDE.md` já existente em `claude/`, mas
ajustando o cabeçalho para indicar que este é o arquivo lido automaticamente. Mantenha
todas as seções (Stack, Ambientes, Convenções obrigatórias, Estrutura de pacotes, Modelo
de Produto v4, Status do Orçamento, PDFs gerados, Endpoints principais, Padrão de commits,
Documentos de referência, Épicos implementados, Decisões técnicas registradas). Atualize
a seção "Documentos de referência" para apontar para `claude/PRD_Pense_Precifique_v6.md`,
`claude/BUSINESS_RULES_Pense_Precifique_v6.md` e `claude/SCENARIOS_Pense_Precifique_v6.md`
(versão v6, não v4).

### 8. Crie um `.gitignore` padrão para projetos Maven/Java (target/, .idea/, *.iml, etc).

Após criar tudo, rode `./mvnw clean compile` para confirmar que o projeto compila
(mesmo sem nenhuma classe além de `PensePrecifiqueApplication.java`). Não inicie o
servidor ainda — não há banco de dados conectado nesta etapa.
