# P-008 — Service + Controller: UsuarioService/UsuarioController (GET /usuarios/me, PUT /usuarios/me/senha)

**Épico:** Épico 1 — Autenticação
**Camada:** back
**Depende de:** P-005 (Security/JWT — para extrair o usuário autenticado do contexto), P-006 (PasswordEncoder via AuthService/SecurityConfig), P-007 (GlobalExceptionHandler, BusinessException)

---

## Contexto para o Claude Code

Esta tarefa cria o último componente do Épico 1: os endpoints autenticados para o
usuário logado consultar seus próprios dados e alterar sua senha.

**Endpoints (CLAUDE.md, "Endpoints principais"):**
| Método | Endpoint | Descrição |
|--------|----------|-----------|
| GET/PUT | /usuarios/me | Dados do usuário logado / alterar senha |

Note que o `CLAUDE.md` agrupa em uma linha, mas conforme `ESTRUTURA.md` original
(`UsuarioController.java // GET /usuarios/me, PUT /usuarios/me/senha`), são dois
endpoints distintos sob o mesmo controller:
- `GET /usuarios/me` — retorna dados do usuário autenticado
- `PUT /usuarios/me/senha` — altera a senha do usuário autenticado, usando
  `AlterarSenhaRequestDTO` (já criado em P-004)

**Como obter o usuário autenticado:** o `JwtAuthenticationFilter` (P-005) já popula o
`SecurityContextHolder` com um `UserDetails` cujo `username` é o `email` do usuário.
O Controller/Service deve extrair esse email do `SecurityContext` (via
`SecurityContextHolder.getContext().getAuthentication().getName()`) e buscar o
`Usuario` correspondente via `UsuarioRepository.findByEmailAndDeletedAtIsNull(email)`.

**Validações de negócio (Service):**
- `PUT /usuarios/me/senha`:
  1. `novaSenha` deve ser igual a `confirmarNovaSenha` (mesma regra de P-006) →
     senão `BusinessException("As senhas não coincidem")`
  2. `senhaAtual` deve corresponder ao hash armazenado (`passwordEncoder.matches`) →
     senão `BusinessException("Senha atual incorreta")`
  3. Atualiza `senhaHash` com `passwordEncoder.encode(novaSenha)`

**DTO de resposta:** crie `dto/response/UsuarioResponseDTO.java` com `id`, `email`,
`ativo`, `createdAt` — **sem** `senhaHash`.

**Cenário de aceite:** sem cenário BDD numerado específico. Critério funcional:
- `GET /usuarios/me` sem token → `401`
- `GET /usuarios/me` com token válido → `200` com `UsuarioResponseDTO` do usuário logado
- `PUT /usuarios/me/senha` com `senhaAtual` incorreta → `400` com "Senha atual incorreta"
- `PUT /usuarios/me/senha` com `novaSenha != confirmarNovaSenha` → `400` com "As senhas
  não coincidem"
- `PUT /usuarios/me/senha` com dados válidos → `200`, e um login subsequente com a nova
  senha funciona (login com a senha antiga passa a falhar)

## Prompt

Cole este prompt no Claude Code:

---

Crie `UsuarioService`/`UsuarioServiceImpl` e `UsuarioController`, além do
`UsuarioResponseDTO`.

### 1. `dto/response/UsuarioResponseDTO.java`
Campos: `id` (UUID), `email` (String), `ativo` (Boolean), `createdAt` (LocalDateTime).
Sem `senhaHash`.

### 2. `service/UsuarioService.java` (interface)
```java
public interface UsuarioService {
    UsuarioResponseDTO getUsuarioAutenticado();
    void alterarSenha(AlterarSenhaRequestDTO request);
}
```

### 3. `service/impl/UsuarioServiceImpl.java`

Anotações: `@Service`, `@RequiredArgsConstructor` injetando `UsuarioRepository`,
`PasswordEncoder`.

Crie um método privado/utilitário `Usuario getUsuarioLogado()` que:
- Obtém o email via `SecurityContextHolder.getContext().getAuthentication().getName()`
- Busca via `usuarioRepository.findByEmailAndDeletedAtIsNull(email)`
- Se não encontrado, lança `BusinessException("Usuário autenticado não encontrado")`
  (caso defensivo — não deve ocorrer na prática se o JWT for válido)

**`getUsuarioAutenticado()`:**
- Retorna `UsuarioResponseDTO` mapeado a partir de `getUsuarioLogado()` (mapeamento
  manual simples é aceitável aqui; não é necessário criar um Mapper MapStruct só para
  este DTO, mas se preferir seguir o padrão MapStruct do projeto, pode criar
  `UsuarioMapper` em `mapper/`)

**`alterarSenha(AlterarSenhaRequestDTO request)`:**
1. `usuario = getUsuarioLogado()`
2. Se `!request.getNovaSenha().equals(request.getConfirmarNovaSenha())` →
   `BusinessException("As senhas não coincidem")`
3. Se `!passwordEncoder.matches(request.getSenhaAtual(), usuario.getSenhaHash())` →
   `BusinessException("Senha atual incorreta")`
4. `usuario.setSenhaHash(passwordEncoder.encode(request.getNovaSenha()))`
5. `usuarioRepository.save(usuario)`

### 4. `controller/UsuarioController.java`

- `@RestController`, `@RequestMapping("/usuarios")`, `@RequiredArgsConstructor`

```java
@GetMapping("/me")
public ResponseEntity<UsuarioResponseDTO> getMe() {
    return ResponseEntity.ok(usuarioService.getUsuarioAutenticado());
}

@PutMapping("/me/senha")
public ResponseEntity<Void> alterarSenha(@Valid @RequestBody AlterarSenhaRequestDTO request) {
    usuarioService.alterarSenha(request);
    return ResponseEntity.ok().build();
}
```

Ambas as rotas já estarão protegidas automaticamente pelo `SecurityConfig` (qualquer
rota não listada como pública exige autenticação).

### Convenções do projeto a seguir:
- Pacotes `service/`, `service/impl/`, `controller/`, `dto/response/`
- Regras de negócio no Service, nunca no Controller

Após criar os arquivos, rode `./mvnw clean compile`, suba `docker-compose up --build` e
teste o fluxo completo:

```bash
# 1. Login (reaproveite o usuário criado no teste do P-007, ou registre um novo)
TOKEN=$(curl -s -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"teste@example.com","senha":"senha1234"}' | jq -r '.token')

# 2. GET /usuarios/me com token
curl http://localhost:8080/usuarios/me -H "Authorization: Bearer $TOKEN"

# 3. GET /usuarios/me sem token (deve dar 401)
curl -i http://localhost:8080/usuarios/me

# 4. Alterar senha
curl -X PUT http://localhost:8080/usuarios/me/senha \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"senhaAtual":"senha1234","novaSenha":"novaSenha123","confirmarNovaSenha":"novaSenha123"}'

# 5. Login com a senha antiga (deve falhar agora)
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"teste@example.com","senha":"senha1234"}'

# 6. Login com a senha nova (deve funcionar)
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"teste@example.com","senha":"novaSenha123"}'
```
