## Contexto para o Claude Code

Mesma lógica do P-012, agora para `ConfiguracaoPrecificacao`. Esta tarefa é menor e mais
simples — é basicamente o mesmo padrão de upsert, aplicado a uma entidade com apenas
dois campos numéricos.

**Endpoint (CLAUDE.md):**
| Método | Endpoint | Descrição |
|--------|----------|-----------|
| GET/PUT | /configuracoes/precificacao | Configurações de preço |

**Diferença importante em relação ao P-012:** para `ConfiguracaoPrecificacao`, faz mais
sentido que `GET` **sempre retorne algo**, mesmo que o usuário nunca tenha configurado
nada — porque a fórmula de precificação (`valorHora × tempo + custo + margem`) precisa
de valores padrão para os cálculos do Épico 4 (Ficha Técnica) não quebrarem.

Portanto:
- `GET /configuracoes/precificacao`:
  - Se existe configuração para o usuário → retorna `200` com os valores salvos
  - Se **não existe** → retorna `200` com valores padrão (`valorHora: 0`,
    `margemPadrao: 0`) **sem criar um registro no banco** (registro só é criado quando o
    usuário salvar pela primeira vez via PUT)

- `PUT /configuracoes/precificacao`:
  - Mesmo padrão de upsert do P-012 (cria se não existir, atualiza se existir)

**Regra de negócio:** `valorHora >= 0` e `margemPadrao >= 0` (já garantido pelo
`@DecimalMin` nos DTOs do P-011 — o Service não precisa duplicar essa validação, mas
deve confiar que `@Valid` no Controller já rejeitou valores negativos antes de chegar
aqui).

**Cenário de aceite:** sem cenário BDD numerado. Critério funcional:
- `GET /configuracoes/precificacao` sem configuração salva → `200` com `valorHora: 0,
  margemPadrao: 0` (valores padrão, sem criar registro)
- `PUT /configuracoes/precificacao` com `valorHora: 25, margemPadrao: 40` → `200`, cria
  o registro
- `GET` após o PUT → `200` com os valores salvos (25, 40)
- `PUT` novamente com novos valores → atualiza (não duplica)
- `PUT` com `valorHora: -5` → `400` (validação `@DecimalMin`)

### 1. `service/ConfiguracaoService.java` (interface)

```java
public interface ConfiguracaoService {
    ConfiguracaoResponseDTO getConfiguracao();
    ConfiguracaoResponseDTO upsertConfiguracao(ConfiguracaoRequestDTO request);
}
```

### 2. `service/impl/ConfiguracaoServiceImpl.java`

Anotações: `@Service`, `@RequiredArgsConstructor` injetando
`ConfiguracaoPrecificacaoRepository`, `UsuarioRepository`.

Reaproveite (ou recrie, se preferir não compartilhar) o padrão de `getUsuarioIdAutenticado()`
do P-012.

**`getConfiguracao()`:**
1. `usuarioId = getUsuarioIdAutenticado()`
2. Busque via `configuracaoRepository.findByUsuarioId(usuarioId)`
3. Se encontrado → mapeie para `ConfiguracaoResponseDTO` e retorne
4. Se **não encontrado** → retorne um `ConfiguracaoResponseDTO` com `id = null`,
   `valorHora = BigDecimal.ZERO`, `margemPadrao = BigDecimal.ZERO`, `updatedAt = null`
   — **sem criar nada no banco** (apenas um objeto "virtual" de resposta com valores
   padrão)

**`upsertConfiguracao(ConfiguracaoRequestDTO request)`:**
1. `usuarioId = getUsuarioIdAutenticado()`
2. Busque via `findByUsuarioId(usuarioId)`
3. Se existir → atualize `valorHora` e `margemPadrao` com os valores do `request`
4. Se não existir → crie uma nova `ConfiguracaoPrecificacao` com `usuarioId` e os
   valores do `request`
5. Salve via `configuracaoRepository.save(...)`
6. Mapeie para `ConfiguracaoResponseDTO` e retorne

### 3. `controller/ConfiguracaoController.java`

```java
@RestController
@RequestMapping("/configuracoes/precificacao")
@RequiredArgsConstructor
public class ConfiguracaoController {

    private final ConfiguracaoService configuracaoService;

    @GetMapping
    public ResponseEntity<ConfiguracaoResponseDTO> getConfiguracao() {
        return ResponseEntity.ok(configuracaoService.getConfiguracao());
    }

    @PutMapping
    public ResponseEntity<ConfiguracaoResponseDTO> upsertConfiguracao(@Valid @RequestBody ConfiguracaoRequestDTO request) {
        return ResponseEntity.ok(configuracaoService.upsertConfiguracao(request));
    }
}
```

### Convenções do projeto a seguir:
- Pacotes `service/`, `service/impl/`, `controller/`
- `BigDecimal` para valores monetários/percentuais — cuidado ao comparar/inicializar
  (`BigDecimal.ZERO`, não `new BigDecimal(0)` ou `0.0`)

Após criar os arquivos, rode `./mvnw clean compile`, suba `docker compose up --build` e
teste (reaproveitando o `$TOKEN` do P-012, ou gerando um novo via login):

```bash
# 1. GET antes de configurar — deve retornar 200 com valores zerados
curl -i http://localhost:8080/configuracoes/precificacao -H "Authorization: Bearer $TOKEN"

# 2. PUT — define valor/hora e margem
curl -i -X PUT http://localhost:8080/configuracoes/precificacao \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"valorHora":25,"margemPadrao":40}'

# 3. GET novamente — deve retornar os valores salvos
curl -i http://localhost:8080/configuracoes/precificacao -H "Authorization: Bearer $TOKEN"

# 4. PUT novamente — atualiza
curl -i -X PUT http://localhost:8080/configuracoes/precificacao \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"valorHora":30,"margemPadrao":50}'

# 5. PUT com valor negativo — deve dar 400
curl -i -X PUT http://localhost:8080/configuracoes/precificacao \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"valorHora":-5,"margemPadrao":40}'
```
