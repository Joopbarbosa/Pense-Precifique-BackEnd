# P-007 — Controller: AuthController (POST /auth/login, /auth/register)

**Épico:** Épico 1 — Autenticação
**Camada:** back
**Depende de:** P-006 (AuthService)

---

## Contexto para o Claude Code

Esta tarefa cria o `AuthController`, expondo os endpoints públicos de autenticação
(`/auth/login` e `/auth/register`), já permitidos sem autenticação pelo `SecurityConfig`
(P-005).

Esta tarefa também cria o `GlobalExceptionHandler`, pois é o primeiro ponto onde
`BusinessException` (criada em P-006) precisa ser traduzida para uma resposta HTTP
adequada (`400 Bad Request`), e onde erros de validação do Bean Validation (`@Valid`)
precisam ser formatados de forma consistente para o front consumir.

**Endpoints (CLAUDE.md, "Endpoints principais"):**
| Método | Endpoint | Descrição |
|--------|----------|-----------|
| POST | /auth/login | Login |
| POST | /auth/register | Cadastro |

**Cenário de aceite:** sem cenários BDD numerados específicos (Épico 1 "sem alterações").
O critério de sucesso é funcional:
- `POST /auth/register` com payload válido → `201 Created` (ou `200 OK`) com `AuthResponseDTO`
- `POST /auth/register` com email duplicado → `400 Bad Request` com mensagem clara
- `POST /auth/register` com `senha != confirmarSenha` → `400 Bad Request`
- `POST /auth/register` com `senha` < 8 caracteres ou `email` inválido → `400 Bad Request`
  com erros de validação por campo
- `POST /auth/login` com credenciais corretas → `200 OK` com `AuthResponseDTO`
- `POST /auth/login` com credenciais incorretas → `400 Bad Request` com "E-mail ou senha
  inválidos"
- `POST /auth/login` com usuário inativo → `400 Bad Request` com "Usuário inativo..."
- Qualquer rota protegida (ex: futura `/usuarios/me`) sem token → `401 Unauthorized`

## Prompt

Cole este prompt no Claude Code:

---

Crie o `AuthController` e o `GlobalExceptionHandler`.

### 1. `controller/AuthController.java`

- Anotações: `@RestController`, `@RequestMapping("/auth")`, `@RequiredArgsConstructor`
  injetando `AuthService`
- Se o Springdoc estiver configurado, adicione anotações `@Tag`/`@Operation` básicas
  para aparecer organizado no Swagger (apenas em `dev`)

**`POST /register`:**
```java
@PostMapping("/register")
public ResponseEntity<AuthResponseDTO> register(@Valid @RequestBody CadastroRequestDTO request) {
    return ResponseEntity.status(HttpStatus.CREATED).body(authService.register(request));
}
```

**`POST /login`:**
```java
@PostMapping("/login")
public ResponseEntity<AuthResponseDTO> login(@Valid @RequestBody LoginRequestDTO request) {
    return ResponseEntity.ok(authService.login(request));
}
```

### 2. `exception/GlobalExceptionHandler.java`

Anotação `@RestControllerAdvice`. Crie também `exception/ErrorResponseDTO.java` (se não
existir) como um record/classe simples para padronizar o corpo de erro:

```java
public record ErrorResponseDTO(
    String message,
    int status,
    LocalDateTime timestamp,
    Map<String, String> fieldErrors // pode ser null quando não há erros de campo
) {}
```

Handlers necessários:

- `@ExceptionHandler(BusinessException.class)` → `400 Bad Request`, corpo
  `ErrorResponseDTO` com `message = ex.getMessage()`, `fieldErrors = null`

- `@ExceptionHandler(MethodArgumentNotValidException.class)` → `400 Bad Request`, corpo
  `ErrorResponseDTO` com `message = "Erro de validação"` e `fieldErrors` populado a
  partir de `ex.getBindingResult().getFieldErrors()` (mapa `nomeDoCampo` →
  `mensagemDeErro`)

- `@ExceptionHandler(Exception.class)` (catch-all) → `500 Internal Server Error`, corpo
  `ErrorResponseDTO` com `message = "Erro interno do servidor"` — **logue a exceção
  original** com `log.error(...)` antes de retornar a resposta genérica (nunca exponha
  stack trace ou mensagem interna ao cliente)

Esta classe será estendida em prompts futuros com handlers para outras exceções
específicas (ex: `ResourceNotFoundException`, `UnauthorizedException` — ver
`ESTRUTURA.md`, pasta `exception/`). Por ora, crie também as classes vazias
`ResourceNotFoundException` e `UnauthorizedException` (estendendo `RuntimeException`,
mesmo padrão de `BusinessException`), já que `ESTRUTURA.md` as lista como parte do
pacote `exception/` — mas **não é obrigatório** adicionar handlers para elas ainda se
nenhum service as lançar; apenas garanta que existam para uso futuro.

### Convenções do projeto a seguir:
- Pacotes `controller/` e `exception/`
- `@Valid` em todos os `@RequestBody` que tiverem DTOs com Bean Validation

Após criar os arquivos, rode `./mvnw clean compile`, suba `docker-compose up --build` e
teste manualmente (via curl, Postman, ou Swagger UI em `http://localhost:8080/swagger-ui.html`):

```bash
# Cadastro
curl -X POST http://localhost:8080/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"teste@example.com","senha":"senha1234","confirmarSenha":"senha1234"}'

# Login
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"teste@example.com","senha":"senha1234"}'

# Cadastro duplicado (deve dar 400)
curl -X POST http://localhost:8080/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"teste@example.com","senha":"senha1234","confirmarSenha":"senha1234"}'
```
