# P-011 — DTOs: EmpresaRequest/Response, ConfiguracaoRequest/Response

**Épico:** Épico 2 — Configuração do Perfil
**Camada:** back
**Depende de:** P-010 (Entities Empresa, ConfiguracaoPrecificacao)

---

## Contexto para o Claude Code

Esta tarefa cria os DTOs de request/response para os dois recursos do Épico 2: perfil
da empresa (artesã) e configuração de precificação.

**Regras de negócio aplicáveis (PRD v6):**
- "Metodologia de precificação: Preço = Custo dos componentes (ficha técnica) + Mão de
  obra (tempo × valor/hora) + Margem de lucro (%)" — `valorHora` e `margemPadrao` são os
  dois parâmetros editáveis pela artesã.
- A tela de Configurações (vista no frontend já implementado) tem 3 abas: "Precificação"
  (valor/hora, margem padrão), "Perfil da empresa" (nome, e-mail, whatsapp, endereço,
  logo), e "Conta" (dados do usuário/autenticação — já coberto pelo Épico 1,
  `UsuarioController`).

**Validações de negócio (a serem aplicadas no Service, P-012/P-013, mas os DTOs já
preparam o terreno com Bean Validation):**
- `nome` da empresa: obrigatório (campo principal do perfil)
- `email` da empresa (se informado): formato válido — pode ser diferente do e-mail de
  login (ex: artesã usa um e-mail pessoal para login e outro comercial para contato)
- `valorHora`: deve ser >= 0
- `margemPadrao`: deve ser >= 0 (percentual; sem limite superior definido — uma artesã
  pode definir margem de 200% se quiser)

**Cenário de aceite:** sem cenário BDD numerado específico. Critério estrutural: DTOs
compilam, com validações de Bean Validation corretas, sem expor `usuarioId` (que é
inferido do usuário autenticado, não enviado pelo cliente).

## Prompt

Cole este prompt no Claude Code:

---

Crie os DTOs de request e response para Empresa e ConfiguracaoPrecificacao, em
`dto/request/` e `dto/response/`.

### 1. `dto/request/EmpresaRequestDTO.java`

Usado em `PUT /empresa`. Campos:
- `nome`: `String`, `@NotBlank(message = "O nome da empresa é obrigatório")`
- `email`: `String`, `@Email(message = "E-mail inválido")` — sem `@NotBlank` (opcional)
- `whatsapp`: `String` (opcional, sem validação de formato rígida — aceitar qualquer
  string; a máscara/formatação é responsabilidade do front)
- `endereco`: `String` (opcional)
- `logoUrl`: `String` (opcional — upload de logo é fora do escopo deste MVP via
  endpoint dedicado; por ora, aceita uma URL/string, podendo vir vazia)

### 2. `dto/response/EmpresaResponseDTO.java`

Campos: `id` (UUID), `nome`, `email`, `whatsapp`, `endereco`, `logoUrl`, `createdAt`,
`updatedAt`. **Sem** `usuarioId` (não é relevante para o cliente) e sem `deletedAt`.

### 3. `dto/request/ConfiguracaoRequestDTO.java`

Usado em `PUT /configuracoes/precificacao`. Campos:
- `valorHora`: `BigDecimal`, `@NotNull`, `@DecimalMin(value = "0", message = "O valor da hora não pode ser negativo")`
- `margemPadrao`: `BigDecimal`, `@NotNull`, `@DecimalMin(value = "0", message = "A margem não pode ser negativa")`

### 4. `dto/response/ConfiguracaoResponseDTO.java`

Campos: `id` (UUID), `valorHora` (BigDecimal), `margemPadrao` (BigDecimal), `updatedAt`.
**Sem** `usuarioId`.

### Convenções do projeto a seguir:
- Pacotes `dto/request/` e `dto/response/`
- `BigDecimal` para valores monetários/percentuais
- Mensagens de validação em português

Após criar os arquivos, rode `./mvnw clean compile` para confirmar que tudo compila.
